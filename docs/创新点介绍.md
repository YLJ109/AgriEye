# 核心创新点介绍

> 本文档梳理项目五大核心创新点，可直接用于国赛答辩、创新报告、论文撰写。

> **⚠️ 口径说明（必读，避免答辩翻车）**
> 当前线上推理使用的是**两个开源预训练 ONNX 权重**（作物病害模型输出 55 类 + 田间害虫模型输出 21 类），
> 本项目的工作集中在：**双模型级联编排、域检查门、细分类映射、农业 RAG 与方案生成**。
> `algorithm/` 目录下的数据合成 → 训练 → 量化链路是**可选的自训扩展路径**，
> 用于将来用自有田间数据微调替换权重，**不是当前推理路径的前置条件**。
> 答辩被问「模型怎么来的」时，请按这个口径回答：开源权重打底 + 本地编排与工程化创新。

> **⚠️ 类别口径（比上一条更容易被追问）**
> "55 类 + 21 类"是**模型输出层的标签数**，不是本项目能报出的类别数。
> 健康叶（13 个）与天敌昆虫（9 个）按设计置零，其余经归并后落到本项目细分类，
> **实际能识别并报出的是 13 个细分类**；方案库覆盖 25 个（含 12 个模型检不出但有方案的类别）。
> **已知短板，务必诚实**：水稻（稻瘟病/白叶枯病/纹枯病）与小麦（锈病/白粉病/赤霉病）
> 这 6 种中国主粮病害不在开源权重覆盖范围内。被问到时答：
> "开源权重覆盖果蔬与经济作物，主粮病害是我们下一步用自有数据微调的重点方向。"
> 不要说"都能识别"——一追问就穿帮。

## 创新点一：多模态区分四类田间问题

### 行业痛点
普通农业 AI 项目只能识别"病害"单一类别，而田间实际问题包括**真菌病害、虫害、土壤缺肥、农药药害**四大类，这四类肉眼极易混淆：
- 缺氮黄化 vs 叶枯病（都是叶片发黄）
- 药害斑驳 vs 真菌病斑（都是叶面斑点）
- 虫害缺刻 vs 病斑坏死（都是叶片破损）

误判直接导致误治——把缺肥当病害喷药、把药害当病害继续施药，越治越糟。

### 本项目方案
- 构建四分类 + 25 细分类别体系（含「其他农业害虫」兜底类），其中 13 个为模型可识别
- **双模型级联**：先跑作物病害模型（YOLOv8n，输出 55 类），无可信检出再跑田间害虫模型
  （YOLOv8m，输出 21 类），两模型都无检出才回退启发式（只给四大类，不编造具体病名）
- **天敌昆虫豁免**：害虫模型里的瓢虫/蜻蜓/蜜蜂/蜘蛛/螳螂/草蛉等益虫不计入虫害判定，
  避免把益虫误报成灾情
- 缺肥类通过叶片黄化模式（H/S/V 通道）与病斑形态联合判别
- 药害类通过斑驳分布 + 施药史辅助判别

### 区别于市面
| 维度 | 市面普通项目 | 本项目 |
|---|---|---|
| 识别类别 | 单一病害 | 病害/虫害/缺肥/药害四类 |
| 细分类 | 3-5 种 | **13 种**可识别（另 12 种有防治方案） |
| 混淆处理 | 无 | 多模态特征联合判别 |

## 创新点二：域检查门 —— 拒绝「无关图片被高置信度误检」

### 行业痛点
检测模型在**训练集分布之外的图片上会给出高置信度的错误答案**。实测本项目就踩过：
一张教室监控画面被害虫模型以 **0.86 置信度判定为「玉米螟」**；食物照片被判成稻瘟病。
对农户来说，这种"一本正经地胡说"比"识别不出来"危害更大——会直接导致错误打药。

### 本项目方案
在**所有模型之前**加一道轻量域检查门（`model_inference.py::_looks_like_plant`）：
- 植被绿占比（Hue 35~85）——有正常作物的最低门槛
- 黄叶占比（Hue 20~35，阈值 0.6）——枯黄/缺氮叶片是本项目的合法识别对象
- Canny 边缘密度（上限 0.08）——截图、UI、文字、建筑边缘密度显著偏高
- 不过门直接返回「未识别」，**不跑模型、不走启发式**，从源头杜绝误报

### 实测标定
| 图片 | 绿占比 | 黄占比 | 边缘密度 | 判定 |
|---|---|---|---|---|
| 蚜虫叶片 | 0.080 | 0.007 | 0.037 | 通过 |
| 玉米病叶 | 0.950 | 0.001 | 0.004 | 通过 |
| 篮球截图 | 0.018 | 0.001 | 0.062 | 拦截 |
| 食物照片 | 0.006 | 0.278 | 0.100 | 拦截 |
| 教室监控 | 0.003 | 0.046 | 0.108 | 拦截 |

### 为什么这是创新点
多数农业 AI 项目只堆模型精度，不处理「用户传了张无关照片」的现实场景。
本项目的做法是把**拒识**当成一等公民——宁可说"没识别出来"，也不给错误答案。

> 附：自训扩展路径（`algorithm/`）保留了完整的小样本训练能力——
> 田间数据增强管线 + 两阶段迁移学习，可用于用自有数据微调替换开源权重。
> 详见文末「自训扩展路径」一节。

## 创新点三：离线轻量化部署

### 行业痛点
农业 AI 多依赖云端推理，农村偏远地区弱网/无网环境下无法使用；且云端推理有延迟、有成本、有隐私顾虑。

### 本项目方案
- **ONNX Runtime 纯 CPU 推理**：`CPUExecutionProvider`，无 GPU 依赖、无 PyTorch 运行时
- **虫害模型懒加载**：93MB 的害虫模型不在启动时常驻，首次真正需要时才载入（PERF-003）
- **推理结果缓存**：按图像内容哈希缓存，重复上传/批量重试不再重复计算
- **RAG 离线**：FAISS 纯 CPU 向量索引 + 本地句向量模型，无外部 API
- **启发式回退**：模型未加载时基于颜色/纹理特征识别，保证任何环境可演示
- **量化链路（自训时使用）**：`algorithm/yolov8_lite/quantize.py` 提供
  PyTorch → ONNX（FP16，体积减半）→ INT8 动态量化（再减约 4 倍，CPU 提速 2-3 倍）

### 落地价值
- 手机小程序/网页端无网络也能识别
- 适配农村偏远场景
- 0 云服务成本，参赛/部署无门槛

## 创新点四：AI 农事大模型顾问（RAG）

### 行业痛点
普通识别系统"只识别不开方"，农户知道是什么病却不知道怎么治；通用大模型不懂农业垂直知识，容易给出错误用药建议。

### 本项目方案
- **农业垂直 RAG 知识库**（`backend/knowledge/`）：
  - 病虫害知识（症状、防治、用药、绿色方案）
  - 缺素症知识（元素、症状、纠正方案）
  - 作物农事日历（按月/节气的种植管理建议）
- **检索流程**：知识切片 → 多语言句向量嵌入 → FAISS 向量索引 → Top-K 检索 → 上下文拼接
- **方案生成**：识别后自动生成用药、施肥、绿色减药、预防措施、农事建议
- **无嵌入模型回退**：jieba 关键词召回，保证轻量环境可用

### 输出示例
识别"稻瘟病"后输出：
- 推荐用药：苯醚甲环唑 1500 倍 / 吡唑醚菌酯 1000 倍
- 绿色方案：枯草芽孢杆菌 800 倍、0.5% 小苏打溶液
- 预防：合理密植、发病初期清病叶、排水降湿
- RAG 知识库补充针对性建议

## 创新点五：识别结果到农事方案的一键闭环

### 行业痛点
多数识别系统止步于"告诉你这是什么病"，农户拿到结果后还要自己查怎么治、什么时候治；
诊断记录也是散落的，无法回溯一季的病虫害发生规律。

### 本项目方案
- **识别即出方案**：推理完成后自动生成用药、施肥、绿色减药、预防措施与农事建议
- **RAG 增强**：把识别结果作为检索条件，从农业知识库取回针对性补充建议
- **档案可追溯**：诊断记录带图片、检测框、置信度、严重程度与时间戳，支持按类别/关键词/时间检索
- **报告导出**：可把当前会话导出为 HTML 报告，便于留存与分享给农技员

### 价值
从"识别"延伸到"决策"，形成拍照 → 识别 → 开方 → 归档的完整闭环。

## 附：自训扩展路径（可选，非当前推理前置条件）

`algorithm/` 保留了完整的自训能力，用于将来用自有田间数据微调替换开源权重：

- **数据合成**：`data_builder/build_dataset.py` 程序合成叶片背景 + 病斑纹理，自动生成 YOLO 标注
- **田间增强**：`data_builder/augment.py` 几何/色彩/噪声/遮挡/天气五类增强，
  模拟逆光、阴天、低质量手机拍摄、叶片遮挡、雨雾等真实田间条件
- **两阶段迁移**：`yolov8_lite/train.py` 先冻结 backbone 微调检测头（小样本防过拟合），
  再全网络小学习率精调
- **量化导出**：`yolov8_lite/quantize.py` PyTorch → ONNX → INT8

> 答辩口径：这条链路体现的是**工程完整性与可扩展性**；
> 当前演示所用的精度来自开源权重 + 本地编排，不是自训产物的精度，请勿混为一谈。

## 总结：创新点矩阵

| 创新点 | 解决痛点 | 技术手段 | 区别市面 |
|---|---|---|---|
| 多模态四分类 | 病害/虫害/缺肥/药害混淆 | 双模型级联 + 益虫豁免 | 普通项目只识别单一病害 |
| 域检查门 | 无关照片被高置信度误检 | HSV 绿/黄占比 + Canny 边缘密度 | 多数项目不做拒识 |
| 离线轻量化 | 农村弱网无法用 | ONNX Runtime CPU + 懒加载 + FAISS 离线 | 依赖云端的不可比 |
| AI 农事顾问 | 只识别不开方 | 农业垂直RAG | 通用大模型不懂农业 |
| 识别到方案闭环 | 结果散落、无法回溯 | 自动出方 + 档案检索 + 报告导出 | 只给结论不给方案 |
